# خادم رمز التحقّق — جاينك

خدمة صغيرة ترسل رمز التحقّق عبر **WhatsApp Cloud API** وتتحقّق منه.

**لماذا سيرفر؟** توكن واتساب لا يجوز أن يكون داخل التطبيق. ملف الـ IPA
يُفكّ في دقائق، ومن يأخذ التوكن يرسل رسائل باسمك ويستنزف رصيدك. هنا
التطبيق يطلب ويتحقّق فقط، والسرّ لا يغادر السيرفر.

بلا أي مكتبات خارجية — مكتبة بايثون القياسية فقط.

---

## ١. شغّله الآن (بلا حساب Meta)

```bash
python3 server/otp_server.py
```

يعمل في **وضع التطوير**: يولّد الرمز ويطبعه في الطرفية بدل إرساله،
ويرجعه في الاستجابة ليعرضه التطبيق. تجرّب التدفّق كاملاً قبل تجهيز Meta.

اختبار سريع:

```bash
curl -s -X POST http://localhost:8787/auth/request-otp \
  -H 'Content-Type: application/json' -d '{"phone":"91112233"}'
```

## ٢. اربط التطبيق

**على المحاكي:** `http://localhost:8787`

**على آيفونك:** لازم عنوان حاسبك على الشبكة (وكلاهما على نفس الواي-فاي):

```bash
ipconfig getifaddr en0        # مثال: 192.168.1.5
```

ثم داخل التطبيق: **حسابي ← حسابات العرض التجريبي ← عنوان خادم رمز
التحقّق** ← اكتب `http://192.168.1.5:8787` ← **اختبر الاتصال** ← حفظ.

لا تحتاج إعادة بناء. لإرجاع الوضع المحلي: نفس الشاشة ← «استخدام الوضع المحلي».

## ٣. فعّل الإرسال الحقيقي عبر واتساب

القيم تُكتب في `.env` **على السيرفر**، لا في سطر الأوامر: سطر الأوامر
يظهر في `ps` لكل مستخدم على الجهاز.

```bash
cd server
cp .env.example .env
nano .env            # املأ WHATSAPP_TOKEN و WHATSAPP_PHONE_NUMBER_ID
bash check-whatsapp.sh   # يفحص التوكن والرقم والقالب قبل التشغيل
bash start-linux.sh
```

`check-whatsapp.sh` يكشف الأعطال الثلاثة التي تفشل **بصمت عند أول
رسالة حقيقية** لا عند التشغيل: توكن مؤقّت منتهٍ (يعيش ٢٤ ساعة)، قالب
غير معتمد أو فئته ليست Authentication، ورمز لغة لا يطابق القالب
(`ar` مقابل `ar_AR`). لا يطبع التوكن ولا يرسله لغير Meta.

عند وجود التوكن يتوقّف `dev_code` عن الظهور نهائياً — التطبيق لا يعرف
الرمز، والمستخدم يستلمه على واتساب فقط.

**شروط من Meta:**
- القالب لازم يكون فئة **Authentication** بزرّ نسخ الرمز؛ قوالب OTP
  بنص حرّ تُرفض.
- رقم الإرسال يجب ألا يكون مستخدماً على واتساب العادي.
- في وضع التجربة تُرسل لخمسة أرقام مضافة يدوياً فقط.
- التوكن المؤقّت ينتهي خلال ٢٤ ساعة — للإنتاج استخدم System User token.
- رسائل Authentication مدفوعة لكل رسالة في عمان.

## الواجهات

| الطريقة | المسار | الجسم | النتيجة |
|---|---|---|---|
| GET | `/health` | — | `{"ok":true,"mode":"dev\|whatsapp"}` |
| POST | `/auth/request-otp` | `{"phone":"91112233"}` | `{"ok":true,"expires_in":300,"resend_after":45}` |
| POST | `/auth/verify-otp` | `{"phone":"...","code":"1234"}` | `{"ok":true,"token":"..."}` |

الأخطاء ترجع `{"error":"...","message":"نص عربي"}` ويعرضه التطبيق كما هو:
`invalid_phone` · `cooldown` · `rate_limited` · `send_failed` ·
`wrong_code` · `expired` · `no_challenge` · `too_many_attempts`

## الحماية المطبَّقة

- الرمز يُخزَّن **مُهشّراً** (PBKDF2-SHA256، ١٢٠ ألف دورة) لا نصاً صريحاً.
- مقارنة بزمن ثابت (`hmac.compare_digest`).
- صلاحية ٥ دقائق، و٥ محاولات كحدّ أقصى ثم يُبطل الرمز.
- مهلة ٤٥ ثانية بين الإرسالين.
- ٣ طلبات لكل رقم كل ١٥ دقيقة، و٢٠ لكل IP كل ساعة.
- الرمز يُحذف فور نجاح التحقّق (لا يُعاد استخدامه).
- توكن الجلسة موقّع بـ HMAC مع صلاحية.

## بدائل واتساب — التحقّق بلا ميتا

الخادم **لا يعرف من هو المزوّد**: تغيّر متغيّر بيئة واحداً فيتبدّل مسار
الإرسال، والتطبيق لا يتغيّر إطلاقاً.

```bash
export OTP_PROVIDER=twilio        # أو infobip / unifonic / telegram / whatsapp
```
وإن لم تحدّده، يكتشفه الخادم من المتغيّرات الموجودة.

### الخيارات

| المزوّد | التوثيق التجاري | التكلفة التقريبية | ملاحظة لعمان |
|---|---|---|---|
| **Unifonic** | خفيف | ~٠.٠٢٠ ر.ع./رسالة | خليجي، يتولّى تسجيل اسم المرسِل لدى هيئة تنظيم الاتصالات |
| **Infobip** | خفيف | ~٠.٠٢٥ ر.ع. | حضور قوي في المنطقة، دعم عربي |
| **Twilio** | متوسط | ~٠.٠٣٠ ر.ع. | عالمي وسهل، لكن اسم المرسِل لعمان يحتاج تسجيلاً |
| **واتساب (ميتا)** | **ثقيل** | ~٠.٠١٥ ر.ع. | أرخص، لكن يلزمه توثيق النشاط + قالب معتمد + رقم مخصّص |
| **Telegram** | لا شيء | مجاني | يتطلّب أن يبدأ المستخدم محادثة مع البوت — للتجربة الداخلية فقط |

⚠️ **قاعدة مهمة في عمان:** الرسائل الدعائية والخدمية (A2P) تحتاج **تسجيل
اسم المرسِل** لدى هيئة تنظيم الاتصالات. المزوّدون الخليجيون
(Unifonic / Infobip) يتولّون هذا نيابة عنك — وهذا سبب تفضيلهم على
مزوّد عالمي يتركك تتعامل مع الهيئة بنفسك.

### الإعداد

```bash
# Unifonic
export OTP_PROVIDER=unifonic UNIFONIC_APPSID="..." UNIFONIC_SENDER="Jaynak"

# Infobip
export OTP_PROVIDER=infobip INFOBIP_API_KEY="..." \
       INFOBIP_HOST="xxxxx.api.infobip.com" INFOBIP_FROM="Jaynak"

# Twilio
export OTP_PROVIDER=twilio TWILIO_ACCOUNT_SID="..." \
       TWILIO_AUTH_TOKEN="..." TWILIO_FROM="+1234567890"
```

نصّ الرسالة يُعدَّل بلا لمس الكود:
```bash
export OTP_TEXT="رمز التحقّق في جاينك: {code}"
```

### ولو أردت واتساب بلا صداع ميتا

مزوّدو الحلول (**BSP**) يتولّون التوثيق واعتماد القالب نيابة عنك:
Unifonic و Infobip و 360dialog و Wati. التكلفة أعلى قليلاً، والإعداد
أيام بدل أسابيع. الخادم يدعمهم بنفس دوال SMS أو بتعديل بسيط.

## الاستضافة المجانية — أيّها نختار؟

| المزوّد | مجاني فعلاً؟ | بطاقة مطلوبة؟ | العيب |
|---|---|---|---|
| **Render** | نعم، دائم | **لا** | ينام بعد ١٥ دقيقة خمول → أول رمز يتأخّر ~٥٠ ثانية |
| **Google Cloud Run** | ٢ مليون طلب/شهر | نعم | بدء بارد ١–٢ ثانية فقط، لكن يلزم تفعيل الفوترة |
| **Koyeb** | خدمة واحدة | نعم | حصّة صغيرة |
| **Fly.io** | رصيد محدود | نعم | لم يعد مجانياً فعلياً |
| **Oracle Always Free** | جهاز كامل للأبد | نعم | إعداد يدوي، وقبول الحساب متقلّب |

### التوصية

**ابدأ بـ Render.** بلا بطاقة، النشر خمس دقائق، وHTTPS مجاني تلقائياً
(وهذا يحلّ مشكلة ATS ويلغي الحاجة لعنوان محلي في التطبيق).

**عالج النوم** برنّة كل ١٠ دقائق من `cron-job.org` (مجاني) على `/health`
— يبقي الخدمة مستيقظة فلا يتأخّر الرمز.

**متى تنتقل؟** حين يزعجك النوم أو تحتاج عدّة نسخ → **Cloud Run**.
الانتقال بلا إعادة كتابة: نفس `Dockerfile` يعمل على الاثنين.

### النشر على Render

1. ارفع المشروع على GitHub
2. `render.com` ← New ← **Blueprint** ← اختر المستودع (يقرأ `render.yaml`)
3. من **Environment**: أضف `WHATSAPP_TOKEN` و `WHATSAPP_PHONE_NUMBER_ID`
4. خُذ العنوان `https://jaynak-otp.onrender.com` وضعه في التطبيق:
   حسابي ← عنوان خادم رمز التحقّق

⚠️ التوكن يُضاف من لوحة Render فقط — **لا يُكتب في `render.yaml`** ولا
يُرفع على GitHub. الملف مضبوط بـ `sync: false` لهذا السبب.

### الانتقال لاحقاً

```bash
# Cloud Run
gcloud run deploy jaynak-otp --source . --region me-central1 --allow-unauthenticated

# أي VPS
docker build -f server/Dockerfile -t jaynak-otp . && docker run -p 80:8787 jaynak-otp
```

**قبل التوسّع:** استبدل التخزين في الذاكرة بـ **Upstash Redis** (طبقة
مجانية) — بلاه تُفقد الرموز عند إعادة التشغيل ولا تعمل مع عدّة نسخ.

## ما يلزم قبل الإنتاج

- [ ] **HTTPS** — بلاه الرمز يمرّ نصاً صريحاً على الشبكة
- [ ] `SESSION_SECRET` ثابت في متغيّر بيئة (وإلا تُبطل الجلسات عند كل تشغيل)
- [ ] استبدال التخزين في الذاكرة بـ **Redis** (يبقى بعد التشغيل ويعمل مع عدّة نسخ)
- [ ] استضافة (Render / Railway / Fly / VPS) بدل حاسبك
- [ ] سجلّات ومراقبة لمحاولات الفشل
- [ ] ربط بقية واجهات التطبيق (الطلبات، التسعير، التوزيع) — راجع `docs/BACKEND.md`

## واجهات الموقع التعريفي

الخادم يخدم `web/` أيضاً بأربع واجهات إضافية:

| الواجهة | الوصف |
|---|---|
| `GET /site/content` | محتوى الموقع القابل للتحرير (عام) |
| `PUT /site/content` | حفظ المحتوى — **جلسة المالك فقط** (`OWNER_PHONE`) |
| `POST /auth/register` | إنشاء حساب بعد التحقّق. الرقم يُؤخذ من الجلسة لا من الجسم |
| `POST /site/notify` | تسجيل رقم للتبليغ عند نزول التطبيق |

تُحفظ في `SITE_DIR` (الافتراضي `./site-data`) في ثلاثة ملفات JSON، مع نسخة
`.bak` قبل كل كتابة وكتابة ذرّية عبر ملف مؤقّت.

```bash
OWNER_PHONE=98061051 ALLOWED_ORIGIN=https://jaynak.com python3 server/otp_server.py
```

`ALLOWED_ORIGIN` يضبط ترويسة CORS (الافتراضي `*`). الكتابة محميّة بالجلسة
لا بالأصل، فضبطه تضييق إضافي لا بديل عن التحقّق.
